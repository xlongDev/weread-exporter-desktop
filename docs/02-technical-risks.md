# 02 - 技术风险清单（Phase 0）

| # | 风险 | 等级 | 缓解方案 |
| --- | --- | --- | --- |
| 1 | 微信读书页面结构/渲染机制变化导致 Canvas Hook 失效 | 高（不可根治） | 保留原引擎不动，变更时只改 Hook 层；UI 明确报错并引导；记录版本探针日志 |
| 2 | 平台风控/账号风险 | 高 | 保留内置温和策略（8~20s 翻页 + 长停顿）且不可调快；UI 明示导出耗时预期（一本数小时）；免责声明 |
| 3 | 导出耗时长（单本 1~3 小时），用户误以为卡死 | 中 | 任务中心展示真实进度（页数/章节/字数/当前章节名）、已耗时；支持取消后继续 |
| 4 | Cookie 明文存放于 browser_profile | 中 | profile 迁移至应用数据目录；文件权限收紧；日志与协议消息绝不包含 Cookie；提供"清除会话" |
| 5 | 浏览器 profile 单实例锁（ProcessSingleton） | 中 | 已有检测；桌面端任务互斥：同一时间仅允许一个抓取任务占用浏览器 |
| 6 | 用户误关浏览器窗口 → 引擎异常 | 中 | Playwright 抛错被引擎捕获 → `task.failed` 事件；可"继续导出"复用已落盘章节 |
| 7 | Python 运行时 + 依赖分发体积 | 中 | macOS 优先；Phase 8 决策（打包独立 Python / PyInstaller）；依赖锁定版本 |
| 8 | Windows 路径/编码（中文文件名、CRLF、路径长度） | 中 | 已有 UTF-8 reconfigure 与文件名清洗；Phase 8 在真实 Windows 上验收 |
| 9 | 引擎进程崩溃/被杀 | 中 | 协议心跳 + 进程退出监听；SQLite 任务状态机；raw 落盘保证数据不丢 |
| 10 | 大体积数据过管道 | 低 | 协议只传元信息；正文/图片走文件系统（引擎已天然落盘） |
| 11 | 无任何既有测试 | 中 | Phase 3 建立引擎回归基线（纯函数单测 + 真实产物冒烟），此后每次核心逻辑改动跑回归 |
| 12 | EbookLib/markdown/playwright 版本漂移 | 低 | requirements 固定 `==` 版本 + venv 锁定；前端 lockfile 提交 |
